# Release Workflow

This document describes the release workflow for Solarus components.

## Repositories

The following are the Git repositories involved in a Solarus release:

| Name       | Repository URL                                          |
|:-----------|:--------------------------------------------------------|
| `engine`   | <https://gitlab.com/solarus-games/solarus>              |
| `launcher` | <https://gitlab.com/solarus-games/solarus-launcher>     |
| `editor`   | <https://gitlab.com/solarus-games/solarus-quest-editor> |

## Checklist

* Create a new release branch in GitLab for the new release, for example `release-2.0.0`, in all of
  the Solarus repositories (`engine`, `launcher` and `editor` in any order).
* If necessary, work final details for the release in the newly created branch.
* When satisfied, merge the release branch to the `master` branch in GitLab. Start with the `engine`
  repository first and wait for the CI/CD pipeline to finish before moving forward. Once the
  pipeline passes, continue with the `launcher` and `editor` repositories in any order. It is
  possible that the CI/CD pipelines for the dependant repositories fail, in which case a simple
  pipeline/job retry should suffice.
* Create a new tag in GitLab for the release, for example `v2.0.0` from the `master` branch. Again,
  start with the `engine` repository, wait for the CI/CD pipeline to finish and then continue with
  the dependant repositories. If the pipelines fail, retry the pipeline/job and it should succeed.
* Proceed with the [making a release](#making-a-release) section.

## Making a Release

> [!note]
> This section requires the [GitLab CLI tool](https://gitlab.com/gitlab-org/cli) to be installed.

After the [checklist](#checklist) is completed, it is time to make a
[project release](https://docs.gitlab.com/user/project/releases/):

* Obtain the GitLab API access token for automation for the `solarus-labs` account.
* Export the token in the environment variable `GITLAB_TOKEN`.
  * For security, it is recommended to store the token in a secured file and export it as follows:
    ```
    export GITLAB_TOKEN=$(< /path/to/file-with-token)
    ```
* If not already done, clone the `engine` repository locally and change directory to it.
* Create notes for the release using [GitLab Markdown](https://docs.gitlab.com/ee/user/markdown/).
  * Save the notes into file with a handy location, for example `release/notes.md`.
* Download the package files generated by the CI/CD pipelines in all the Solarus repositories.
  * Save the package files into a handy location, for example `release/solarus-x64-v2.0.0.zip`.
* Perform the release using the GitLab CLI tool:
  ```
  glab release create TAG -F release/notes.md release/*.zip
  ```
* The release is now available in: <https://gitlab.com/solarus-games/solarus/-/releases/TAG>

> [!tip]
> Additional release assets can be added after the release is created.

Example release notes file for version `v2.0.0`:
```markdown
## Solarus 2.0.0 (2025-04-01)

The multiplayer and dark mode update is finally here!

* Watch the [release trailer](https://www.youtube.com/watch?v=X_hJDhWXxU8) for details.
* New [documentation website](https://docs.solarus-games.org/) available.
* Visit the [Solarus Games website](https://solarus-games.org/) for more information.

### Changelogs

* [Engine](https://gitlab.com/solarus-games/solarus/-/blob/v2.0.0/changelog.md?ref_type=tags)
* [Launcher](https://gitlab.com/solarus-games/solarus-launcher/-/blob/v2.0.0/CHANGELOG.md?ref_type=tags)
* [Editor](https://gitlab.com/solarus-games/solarus-quest-editor/-/blob/v2.0.0/changelog.md?ref_type=tags)
```
